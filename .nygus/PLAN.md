# Plan

The existing application is the runnable skeleton. Each step ends with a user-visible workflow and its stored or derived result.

- [ ] 0. Polish the SBS Coach dashboard. Done when week/status, subscription usage, primary chat, and collapsible settings/history/memory form a clear responsive panel without losing existing controls.
- [ ] 1. Publish the confirmed Strive research comparison. Done when the report identifies new official inspirations, overlaps, source links, and decompilation limits.
- [ ] 2. Faster set entry. Add copying from a comparable set/session and bulk field application with undo. Done when a workout interaction updates the intended compatible rows and undo restores every prior value.
- [ ] 3. Routine exercise alternatives. Configure alternatives on a slot and choose one in a live workout. Done when saved routines retain the alternatives and the logged replacement reads its own exercise history.
- [ ] 4. Deload-aware history. Store an explicit deload marker separately from generic progression exclusion and show/filter it in strength review. Done when edited history and charts preserve the marker while volume and attendance remain unchanged.
- [ ] 5. SBS cycle recap. Derive a cycle review from saved sessions and decisions. Done when an ended cycle shows source-backed lift changes, sessions, PRs, training-max changes and Coach decisions.
- [ ] 6. Personal Home cards. Pin or hide existing cards and expose an SBS cycle card. Done when layout choices persist and disabling SBS removes only its card.
- [ ] 7. Load calibration. Guide a first working-load session for unknown lifts. Done when confirmed loads become routine targets and known targets are untouched.
- [ ] 8. Exercise comparison charts. Compare two exercises for a compatible metric and range. Done when units, labels, and missing-data states are clear.
- [ ] 9. Workout milestone images. Extend current workout image sharing with an optional verified PR/milestone card. Done when sharing does not include notes or private measurements.
- [ ] 10. Self-contained plan links. Generate a plan link and review/import it in a second browser. Done when invalid/oversized input does not mutate user data and the sharing URL carries no plan data to the server.
- [ ] 11. Full verification and review. Done when the frontend/API suites and both production image builds pass, the production smoke checks pass, and Production/Data/Security review findings are addressed or recorded.
- [ ] 12. Deploy openGym. Done when a pre-deploy data backup exists, current images are recorded, only the two openGym services update, health passes, and rollback references are written here.
- [ ] 13. Evidence and delivery. Done when every SPEC criterion has a command or observed-behavior result and README/research evidence matches the deployed build.
